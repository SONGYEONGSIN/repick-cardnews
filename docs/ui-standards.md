# 화면 표준

새 화면·패널을 만들 때 지키는 규칙. **여백이 남는 화면이 반복해서 나와서** 그때그때 고치는 대신
여기에 못 박는다.

---

## 1. 패널 골격 — 제목 / 구분선 / 박스 안 내용

`SectionHead` 가 표준이다. **제목과 구분선이 한 몸**이므로 따로 그리지 않는다.
**내용은 테두리 박스 안에** 들어간다.

```tsx
<section className="flex flex-col gap-4">
  <SectionHead title="파일로 저장" aside="이 컴퓨터 안에만 남아요" />
  <div className="flex flex-col gap-4 rounded-xl border border-hair p-6">
    {/* 내용 */}
  </div>
</section>
```

- `aside` 는 **그 패널의 성격**을 한 줄로 (어디까지 나가는가, 무엇이 필요한가)
- **제목을 박스 안에 넣지 않는다.** 박스 안 제목과 박스 밖 제목이 나란히 있으면
  같은 위계인데 다르게 보인다
- **내용은 반드시 박스 안에 넣는다.** 박스 없는 패널과 박스 있는 패널이 나란히 놓이면
  한쪽만 허공에 뜬 것처럼 보인다 — 실제로 그렇게 보인다는 지적을 받았다
- 박스는 패널마다 **하나**다. 2단이면 그 격자를 박스 안에 넣는다(칸마다 박스를 두지 않는다)

## 2. 폭 — 본문은 폭을 다 쓴다

**`max-w` 로 화면 절반을 비우지 않는다.** 남는 여백은 의도가 아니라 결함으로 읽힌다.

- **이미 칸 안에 있는 문단은 제한하지 않는다.** 2단 격자의 칸이 이미 폭을 정한다 — 거기 또
  제한을 걸면 두 번 조여서 칸 안에 빈 곳이 생긴다
- **전체 폭을 쓰는 문단만** 읽기 폭으로 제한한다: `max-w-[46rem]`
- **`ch` 단위를 쓰지 마라.** `ch` 는 라틴 문자 `0` 의 폭 기준이라 한글에서는 의도한 폭의 절반쯤
  된다(`62ch` ≈ 한글 30자). 이 프로젝트 글은 전부 한글이므로 `rem` 으로 잡는다
- 문단을 제한했으면 **남는 폭은 다른 내용이 채운다** — 목록·미리보기·부가 컨트롤
- 채울 게 없으면 그 화면은 2단이 아니라 1단이다. 억지로 나누지 않는다

## 3. 2단 — 내용이 둘로 나뉠 때만

```tsx
<div className="grid gap-6 xl:grid-cols-2 xl:items-start">
```

- `xl` 미만에서는 자동으로 1단이 된다(세로로 쌓임)
- **왼쪽은 설명·상태, 오른쪽은 조작·결과** 를 기본으로 둔다. 읽고 나서 누르는 순서다

**칸을 늘릴지 말지는 테두리가 정한다:**

| 두 칸의 내용 | 정렬 |
|---|---|
| **테두리 박스** | 늘린다(기본 `stretch`) + 박스에 `flex-1`. 나란한 박스의 아래가 들쭉날쭉하면 결함으로 읽힌다 |
| 테두리 없는 글·컨트롤 | `xl:items-start`. 안 그러면 짧은 칸이 억지로 늘어나 빈 곳이 생긴다 |

실측 예: 내보내기의 `파일로 저장`(156px)과 `저장될 파일`(284px)이 128px 어긋나 있었다.

## 4. 되돌릴 수 없는 조작은 헤더로

"처음부터 다시" 처럼 되돌릴 수 없는 조작은 **본문 맨 아래가 아니라 헤더 오른쪽**에 둔다.

- 본문 흐름(만들고 → 고르고 → 내보내고)과 섞이면 실수로 누르기 쉽다
- 헤더는 "이 화면 전체에 대한 조작" 자리다 — 되돌아가기와 같은 줄
- 확인 단계는 그 자리에서 버튼이 바뀌는 방식으로. `window.confirm` 은 쓰지 않는다

## 5. 호버 — 두 가지뿐

버튼 종류마다 호버가 제각각이면(투명도·테두리·글자색이 섞이면) 같은 위계인데 다르게 반응한다.

| 종류 | 호버 |
|---|---|
| **채움**(`bg-ink`, 채운 칩) | `hover:opacity-85` — 배경이 이미 검정이라 색을 더 못 바꾼다 |
| **선**(테두리만, 탭·옵션 포함) | `hover:bg-hair-soft` (+ 테두리·글자색 강조는 덤) |

- **`disabled` 에서는 호버가 안 걸려야 한다** — `disabled:hover:bg-transparent` 를 함께 준다
- 사진이 들어간 줄에는 `opacity` 를 쓰지 마라. 사진이 흐려지면 무엇인지 안 보인다 — 배경으로 표시한다
- **움직임으로 반응하지 마라**(`translate`·`scale`). 한 요소만 떠오르면 같은 위계인데 혼자 다르게
  군다. 첫 화면(허브)의 카드가 그랬다
- **브랜드 색은 이 규칙과 별개다.** 첫 화면은 브랜드를 보여 주는 자리라 `plum` 테두리를 유지한다 —
  호버가 배경으로 반응한다는 규칙만 같이 지킨다

## 6. 빈 자리 박스

아직 내용이 없는 자리는 `PLACEHOLDER_BOX`(`@/components/ui`) 하나를 쓴다.

사진 올리는 곳과 카드가 나올 자리가 **나란히 놓이므로 같은 골격이어야 한다.** 예전엔 모서리와
세로 여백이 달라 한쪽만 커 보였다 — 값을 각자 적으면 다시 갈라진다.

## 7. 색

액센트 색을 쓰지 않는다. 강조는 **검정 채움**(`bg-ink text-surface`)·**테두리 2px**·**굵기**로만.

예외는 **색 자체가 내용일 때**뿐이다 — 카드 미리보기, 테마 견본. 그 경우 색은 `THEMES` 같은
데이터에서 오고 인라인 `style` 로 준다(하드코딩 리터럴은 여전히 금지).

## 8. 검증

- `npm run design:audit` — 이모지·하드코딩 색상·금지 폰트 + 폭 스위프(390~1920) 가로 오버플로 0
  + **정렬 게이트**
- **정렬 게이트가 나란한 것들의 `top`·`height` 를 잰다.** 눈으로는 8px 을 못 본다 — 실제로
  세 번(빈 자리 박스 289/179, 두 칸 시작 141/133, 내보내기 박스 156/284) 사람이 지적해서야 알았다.
  사진과 카드가 있어야 열리는 화면(작업대·내보내기)까지 밟는다. 카피 생성은 **가짜 응답으로
  가로채** Claude 할당량을 쓰지 않는다
- 나란한 것을 새로 만들면 **게이트에 한 줄 추가한다**(`scripts/design-audit.mjs` 의 `정렬` 절)
