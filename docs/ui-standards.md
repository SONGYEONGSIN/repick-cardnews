# 화면 표준

새 화면·패널을 만들 때 지키는 규칙. **여백이 남는 화면이 반복해서 나와서** 그때그때 고치는 대신
여기에 못 박는다.

---

## 1. 패널 골격 — 제목 / 구분선 / 박스 안 내용

`SectionHead` 가 표준이다. **제목과 구분선이 한 몸**이므로 따로 그리지 않는다.
**내용은 테두리 박스 안에** 들어간다.

```tsx
<section className="flex flex-col gap-4">
  <SectionHead title="파일로 저장" aside="이 컴퓨터 안에만 남아요" />
  <div className="flex flex-col gap-4 rounded-xl border border-hair p-6">
    {/* 내용 */}
  </div>
</section>
```

- `aside` 는 **그 패널의 성격**을 한 줄로 (어디까지 나가는가, 무엇이 필요한가)
- **제목을 박스 안에 넣지 않는다.** 박스 안 제목과 박스 밖 제목이 나란히 있으면
  같은 위계인데 다르게 보인다
- **내용은 반드시 박스 안에 넣는다.** 박스 없는 패널과 박스 있는 패널이 나란히 놓이면
  한쪽만 허공에 뜬 것처럼 보인다 — 실제로 그렇게 보인다는 지적을 받았다
- 박스는 패널마다 **하나**다. 2단이면 그 격자를 박스 안에 넣는다(칸마다 박스를 두지 않는다)

## 2. 폭 — 본문은 폭을 다 쓴다

**`max-w` 로 화면 절반을 비우지 않는다.** 남는 여백은 의도가 아니라 결함으로 읽힌다.

- 긴 문단만 읽기 폭으로 제한한다: `max-w-[62ch]`. 문단이 화면 끝까지 늘어나면 읽기 어렵다
- 문단을 제한했으면 **남는 폭은 다른 내용이 채운다** — 목록·미리보기·부가 컨트롤
- 채울 게 없으면 그 화면은 2단이 아니라 1단이다. 억지로 나누지 않는다

## 3. 2단 — 내용이 둘로 나뉠 때만

```tsx
<div className="grid gap-6 xl:grid-cols-2 xl:items-start">
```

- `xl` 미만에서는 자동으로 1단이 된다(세로로 쌓임)
- `items-start` 를 붙인다 — 없으면 짧은 칸이 긴 칸 높이만큼 늘어난다
- **왼쪽은 설명·상태, 오른쪽은 조작·결과** 를 기본으로 둔다. 읽고 나서 누르는 순서다

## 4. 되돌릴 수 없는 조작은 헤더로

"처음부터 다시" 처럼 되돌릴 수 없는 조작은 **본문 맨 아래가 아니라 헤더 오른쪽**에 둔다.

- 본문 흐름(만들고 → 고르고 → 내보내고)과 섞이면 실수로 누르기 쉽다
- 헤더는 "이 화면 전체에 대한 조작" 자리다 — 되돌아가기와 같은 줄
- 확인 단계는 그 자리에서 버튼이 바뀌는 방식으로. `window.confirm` 은 쓰지 않는다

## 5. 색

액센트 색을 쓰지 않는다. 강조는 **검정 채움**(`bg-ink text-surface`)·**테두리 2px**·**굵기**로만.

예외는 **색 자체가 내용일 때**뿐이다 — 카드 미리보기, 테마 견본. 그 경우 색은 `THEMES` 같은
데이터에서 오고 인라인 `style` 로 준다(하드코딩 리터럴은 여전히 금지).

## 6. 검증

- `npm run design:audit` — 이모지·하드코딩 색상·금지 폰트 + 폭 스위프(390~1920) 가로 오버플로 0
- 스위프는 `/`·`/cardnews`·`/info` 만 훑는다. **사진과 카드가 있어야 열리는 화면(작업대·내보내기)은
  자동으로 안 잡히므로 사람이 봐야 한다**
