# 콘티 스튜디오 — 후속 작업과 확인 절차

`feat/card-studio` 브랜치(75+ 커밋, `a18c350..`) 완료 시점 기준. 최종 브랜치 리뷰가 남긴
후속 항목과, 이 환경에서 검증하지 못해 사람이 확인해야 하는 것들.

---

## 1. 사람이 확인해야 하는 것 (최우선)

**이 앱은 어느 기계에서도 저장이 한 번도 성공한 적이 없다.** `knowledge/ledger.jsonl` 이 0 바이트다.
브라우저 자동화가 이 개발 환경에서 로컬 서버에 도달하지 못해, 아래는 전부 코드 정독과 산술로만
검증됐다. 렌더 계층 결함 9건을 그 방식으로 잡아냈지만, 그 방식이 못 잡는 것이 남아 있다.

확인용 자산은 이미 있다 — `knowledge/references/cardnews/` 에 이미지 8장(정원 6장이라 트레이
교체 경로까지 함께 확인된다).

```
npm run dev   # http://localhost:3500
```

| 순서 | 조작 | 확인할 것 |
|---|---|---|
| 허브 | 카드뉴스 선택 | 두 진입 카드와 미리보기 SVG 가 **보이는지**(투명 렌더 아님) |
| ① 사진 | `knowledge/references/cardnews/` **폴더를 드롭** | **★ 최우선.** 8장이 파일명 순으로 들어오는지. 「이미지 파일이 없어요」가 뜨면 폴더 드롭이 실패한 것 |
| ① 사진 | 「폴더 선택」 버튼도 눌러 보기 | 드롭이 실패해도 이 경로는 동작해야 한다 |
| ② 순서 | 손잡이 드래그, 그리고 **Tab → Space → 화살표 → Space** | 키보드로도 순서가 바뀌는지 |
| ② 순서 | 트레이의 「자리 바꾸기」 셀렉트 | 슬롯 교체가 되는지 |
| ③ 주제 | 키워드 입력 후 생성 | 카피가 **사진 내용을 반영**하는지 |
| ④ 편집 | 카드 선택 · 레이아웃 토글 · 슬라이더 | 스테이지 즉시 반영. **역할 배지(문제/증거/해결책)가 가로 전체 막대가 아닌지 ★** |
| ⑤ 저장 | 「폴더에 저장」 | `cardnews/<슬러그>-<MMDD>/` 에 PNG 생성 |
| **PNG** | **Finder 에서 파일 열기** | **1080×1350 인지 · 글자가 잘리지 않았는지 · 사진 위 텍스트가 읽히는지** |

정보전달도 같은 폴더로 `/info` 에서 한 번 — 대표 사진 고르기, 항목 드래그, `informationsend/…/1.png`.

**폭·키보드 검증**: 창을 1280 / 1440 / 1920 폭으로 두고 두 플로우를 훑어 가로 스크롤바가 없는지,
Tab 만으로 전 경로에 도달하는지.

가장 중요한 두 가지에 ★ 를 달았다. 폴더 드롭과 역할 배지는 **수정했지만 실물을 본 적이 없다** —
전자는 브라우저 DOM API 계약, 후자는 CSS 추론에 근거한 수정이다.

## 2. 후속 PR 감 (최종 리뷰 지적, 우선순위 순)

### P1
- **`COMPACT_ITEMS_MIN` 공유 상수화** — `CardRenderer.tsx:36` 의 `items.length >= 5` 와
  `infosend/reducer.ts` 의 `bandForItems` 가 서로를 전제하면서 묶는 것이 없다. `layout-utils.ts` 에
  `export const COMPACT_ITEMS_MIN = 5` 를 두고 양쪽이 쓰게 한다.
  **이 브랜치에서 17번 반복된 결함 패턴의 살아남은 인스턴스다.**
- **`bandFor` 임계 재유도** — `cardnews/reducer.ts` 의 `steps >= 4` 가 주석의 산술에서 유도되지
  않았다. 주석의 574px 도 `SplitPhotoCard` 의 6px borderTop 을 빠뜨려 실제는 568px.
  리뷰어 추정으로 2~3 스텝 카드가 패딩을 침범한다. `steps >= 2` 로 낮추는 것을 검토.
- **카드뉴스 밴드 슬라이더 상한** — `CardInspector.tsx:143` 이 `max={70}` 인데 스펙은 0.2~0.5.
  0.70 이면 글 상자가 231px 로 줄어 눈에 보이게 잘린다. `max={50}` 로.

### P2
- **카드 본문의 `<h1>`** — `CardnewsBody`·`InfographicBody` 가 각각 `h1` 을 내서 편집 화면 DOM 에
  h1 이 13개쯤 생긴다. PNG 에는 의미가 없고 계산 스타일도 동일하니 `div` 로 바꾼다.
- **`RenderCard.badge` 이름 충돌** — 페이지 카운터인데 `HookCard.badge`(역할 칩)와 이름이 같아
  리뷰에서 두 번 혼동을 샀다. `counter` 로 개명.
- **`aria-pressed` 오용** — `PhotoGrid` 가 토글이 아닌 두 동작(빼기 / 대표 고르기)에 쓰고 있다.
  카드뉴스는 `aria-label` 만, 정보전달은 `radiogroup`/`radio`.
- **손상된 원장 줄** — `ledger.ts` 의 `JSON.parse` 가 던지면 허브 전체가 에러 페이지가 된다.
  파싱 실패 줄은 건너뛴다.
- **글자수 제한 방식 불일치** — 카드뉴스는 초과를 빨갛게 표시하되 입력을 막지 않고(의도),
  정보전달은 `maxLength` 로 하드 차단한다. 스키마 위반은 없으나 같은 도구에서 다르게 동작한다.

### P3
- 빈 슬러그 폴백 불일치(`useExport` 는 `|| "card"`, `paths.ts` 는 없음), `save` 라우트의 keyword 무제한
- `INPUT` 클래스 문자열이 4개 파일에 중복 — 프로젝트 자체 규칙(3회 이상 추출)을 이미 넘겼다
- `design-tokens.ts` ↔ `globals.css` hex 중복 / 포커스 링 클래스 중복 / `text-white`·`#111111` 미토큰화
- 테마 선택이 보더 색에만 의존(WCAG 1.4.1) — 비색상 표식 추가
- 레이아웃 3형제의 prop 관례 불일치(`theme` vs `accent`)
- 항목 id 가 `item-${i}` 파생이라 비마지막 항목 삭제 시 포커스 점프
- 순수 헬퍼의 미검증 경계(`isFourFive` 오차 경계·0/음수, `parseDataUrl` 빈 본문, `layout-utils` NaN)

### 확인 후 불필요로 판정된 것
- `TextOnlyCard` 의 `position:relative` 누락 — 배지가 `CardFrame`(relative)에 해석돼 렌더 동일
- dnd-kit 인라인 transition 의 reduced-motion — `globals.css` 가 전역으로 이미 강제

## 3. 이 브랜치에서 배운 것

리뷰가 잡은 **17건의 계획 결함이 전부 한 형태**였다 — *눈으로 고른 숫자나 enum 이 두 번째 파일과
모순되는 것*. 밴드 0.6·0.35, 슬라이더 `min=20`, `steps>=4`, `slice(-0)`, 접히는 레일에 단일 행 전략,
`photoId` 이중 폴백, `action` 편집기 누락, `onPhoto` 분기 누락.

각 파일만 보면 전부 옳다. 합쳐야 어긋난다. 파일 단위 리뷰가 구조적으로 못 보는 종류이고,
그래서 **최종 브랜치 리뷰가 이 프로젝트에서 가장 값진 게이트였다** — 차단 결함 2건도 거기서 나왔다.

다음에 같은 규모를 할 때의 교훈: **두 파일이 같은 숫자를 알아야 하면 상수로 묶는다.** 주석으로
"저쪽이 5에서 켠다" 라고 쓰는 순간 그것은 결함 대기 상태다.
