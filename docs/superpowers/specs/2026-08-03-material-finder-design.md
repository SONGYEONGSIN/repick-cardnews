# 소재 찾기 — 설계

카드뉴스 주제를 직접 타이핑하는 대신 **뜨는 소재 중에서 골라 오는** 전용 화면.

지금은 주제 화면의 보조 패널 하나뿐이고, 그것도 **100초를 기다려야 결과가 나오는 길 하나**밖에
없다. 어디서 가져오는지 고를 수 없고, 빨리 훑어볼 수도 없다.

---

## 확인된 제약 — 설계의 출발점

**추측이 아니라 실제 호출로 확인한 것들이다. 여기서 벗어나는 설계는 만들 수 없다.**

### 1. 네이버는 후보를 만들 수 없다

| API | 요청 요건 | 확인 결과 |
|---|---|---|
| 검색어트렌드 | `keywordGroups` 필수 | 준 키워드의 검색 비중만 돌려줌 |
| 쇼핑인사이트 | `keyword` 필수 | 빼고 부르면 `should have required property 'keyword'` |

**둘 다 "자(ruler)"지 "샘(source)"이 아니다.** 데이터랩에는 "요즘 뭐가 뜨나"를 돌려주는 API 가
없다(웹 화면의 인기검색어는 API 미공개, 실시간 검색어는 2021년 폐지).

→ **"유튜브에서 가져올까 네이버에서 가져올까"는 만들 수 없다.** 만들면 네이버 쪽이 항상 빈손이다.
축은 **어디서 가져오나(유튜브)** × **무엇으로 줄 세우나(네이버·Claude)** 두 개다.

### 2. 유튜브 호출 비용이 모드를 가른다

| 호출 | 유닛 | 하루 상한(10,000유닛) |
|---|---|---|
| `videos.list` (급상승) | **1** | 사실상 무제한 |
| `search.list` (키워드 검색) | **100** | **하루 100회** |

키워드 검색은 무한이 아니다 — 화면이 이 사실을 감추면 안 된다.

### 3. 유튜브 카테고리는 지역별로 지원이 다르다

한국에서 `mostPopular` 지원 확인: `26`(살림·요리·꿀팁), `22`(일상·브이로그),
`28`(생활기술·가전). **`27` Education·`19` Travel 은 `notFound`** — 다시 넣지 말 것.
`24/25/17/20/23`(연예·정치·스포츠·게임·코미디)은 지원되지만 잡음이 커서 의도적으로 뺐다.

### 4. 네이버 쇼핑 분야 ID (대표 키워드로 역추적, 2026-08-03 실측)

`50000000` 패션의류 · `50000001` 패션잡화 · `50000002` 화장품/미용 · `50000003` 디지털/가전
`50000004` 가구/인테리어 · `50000005` 출산/육아 · `50000006` 식품 · `50000007` 스포츠/레저
`50000008` 생활/건강

**한 키워드가 여러 분야에서 데이터를 낸다**(`세탁세제` → 출산/육아·생활/건강 둘 다). 그래서
쇼핑인사이트는 **분야를 사용자가 골라야** 의미가 생긴다. 자동으로 정할 수 없다.

## 무엇을 만드나

### 화면 위치 — 주제 화면에서 여는 전용 화면

스텝 인디케이터(`주제 → 만들기 → 내보내기`)는 **그대로 3단계**다. 소재 찾기를 4번째 스텝으로
넣으면 필수처럼 보이는데, 이것은 **선택적 도구**다.

```
주제 화면 ──[소재 찾기]──▶ 소재 찾기 화면 ──[이 소재로]──▶ 주제 화면 (주제 칸 채워짐)
    │                                    └──[그만두기]──▶ 주제 화면 (그대로)
    └── 직접 타이핑하는 길은 언제나 열려 있다
```

기존 `TopicSuggestPanel` 은 이 화면으로 옮겨 가고, 주제 화면에는 **버튼 하나**만 남는다.

### 세 가지 모드 — 속도로 갈린다

지금의 문제는 **100초 아니면 아무것도 없다**는 것이다. 빠른 길을 낸다.

| 모드 | 무엇 | 걸리는 시간 | Claude |
|---|---|---|---|
| **급상승** | 유튜브 인기 급상승 영상 제목 그대로 | **1~2초** | 안 씀 |
| **키워드로 찾기** | 준 키워드로 유튜브 검색, 영상 제목 그대로 | **1~2초** | 안 씀 |
| **소재 추천** | 급상승 + Claude 가 생활 정보 주제로 다듬음 | **100초** | 씀 |

**급상승·키워드 찾기는 영상 제목을 날것 그대로 보여 준다.** 다듬지 않는다 — 낚시성 제목이면
사용자가 안 고르면 된다. 제목을 고를 수 있고, 고른 뒤 주제 칸에서 직접 다듬는다.

**모드마다 순위 근거가 다르다** — 아래 참조.

#### 급상승
- 카테고리 **다중 선택** (살림·요리·꿀팁 / 일상·브이로그 / 생활기술·가전). 기본은 셋 다
- 순위: **유튜브 인기 순서 그대로**. 데이터랩을 붙이지 않는다 — 영상 제목은 문장이라
  검색어로 넣을 수 없다
- 카테고리 하나가 실패해도 나머지로 진행(기존 `combineCategoryResults` 그대로)

#### 키워드로 찾기
- 키워드 입력 → `search.list`
- 순위: **유튜브 관련도 순서 그대로**
- **하루 100회 상한을 화면에 적는다.** 유튜브가 잔여량을 알려 주지 않으므로 "하루 100번까지"
  라고만 말하고, 남은 횟수를 지어내지 않는다
- 한도 초과(`quotaExceeded`)는 한국어로 구분해 안내

#### 소재 추천
- 지금 파이프라인 그대로 (급상승 → Claude 추리기 → 순위 렌즈)
- 순위 렌즈를 **고를 수 있다** ↓

### 순위 렌즈 — 소재 추천 모드에서만

| 렌즈 | 무엇으로 줄 세우나 | 조건 |
|---|---|---|
| **검색어트렌드** (기본) | 통합검색, 30~49세 여성 검색 비중 | 네이버 키 필요 |
| **쇼핑인사이트** | 쇼핑 검색 클릭 비중 | 네이버 키 + **분야 선택 필수** |
| **Claude 판단** | Claude 가 본 관련성 | 없음 |

- 네이버 키가 없으면 앞의 둘은 **고를 수 없는 상태**로 두고 이유를 적는다(숨기지 않는다)
- **쇼핑인사이트를 고르면 분야를 함께 고른다.** 30~40대 맘 기준 기본 후보:
  출산/육아 · 식품 · 생활/건강 · 가구/인테리어. 전체 9개도 고를 수 있다
- 쇼핑인사이트는 **물건 소재일 때만 의미가 있다** — `감자전 레시피` 로는 데이터가 안 나온다.
  이 한계를 렌즈 설명에 적는다
- 어떤 렌즈든 **실패하면 Claude 순위로 폴백**하고 그 사실을 밝힌다(기존 정책 유지)

### 출처 표시 — 결과 위에 항상

```
후보   유튜브 인기 급상승(한국) · 살림·요리·꿀팁, 일상·브이로그
순위   유튜브 인기 순서 그대로
```

`후보`/`순위` 두 줄 구조는 지금 것을 그대로 쓴다. **유튜브와 네이버가 경쟁하는 출처처럼 보이면
안 된다** — 단계가 다르다.

## 상태와 오류

모든 모드가 공통으로 다뤄야 하는 것:

| 상태 | 화면 |
|---|---|
| 아직 안 누름 | 무엇을 할지 + 얼마나 걸리는지 |
| 도는 중 | 경과 시간, 그만두기. 100초짜리는 예상 시간 초과 문구 전환 |
| 결과 있음 | 목록 + 출처 두 줄 |
| **결과 0개** | "직접 입력하세요"로 되돌림. 빈 목록만 두지 않는다 |
| 일부만 가져옴 | 건너뛴 카테고리를 밝힘 |
| 오류 | **한국어만.** 영문·raw JSON 노출 금지 |

- 같은 요청 중복 발사 금지(100초짜리가 겹치면 할당량만 먹는다)
- 화면을 떠나면 요청 abort
- `/api/topics` 는 이 PC 브라우저에서만(`local-guard`) — 새 엔드포인트도 동일

## 범위

### 이번에 만드는 것
- 소재 찾기 전용 화면 + 주제 화면 연결
- 급상승 모드(카테고리 다중 선택) · 키워드 찾기 모드 · 소재 추천 모드
- 순위 렌즈 선택 + 쇼핑인사이트 분야 선택
- 유튜브 `search.list` 연동, 쇼핑인사이트 연동

### 범위 밖
- 찾은 소재 **보관함**(나중에 다시 보기) — 저장소 설계가 따로 필요하다
- 유튜브 잔여 할당량 표시 — API 가 알려 주지 않는다
- 네이버 연관검색어·자동완성 — 공식 API 가 없다
- 예약 발행(F) — 별건

## 테스트

이 저장소 vitest 는 `environment: "node"` 라 **React 렌더 테스트를 쓸 수 없다.**
판단 로직은 전부 순수 함수로 빼서 테스트하고, 컴포넌트에는 JSX 와 배선만 남긴다.

**RED 를 먼저 확인하고 구현한다.** 화면은 폭 스위프(390~1920) + `npm run design:audit` 로 검증한다.

**실제 `/api/topics` 호출은 Claude 할당량을 쓴다(1회 100초).** 개발 중에는 부르지 않고, 최종
확인 때 한 번만 부른다. 급상승·키워드 찾기는 Claude 를 안 쓰므로 자유롭게 확인해도 된다.
