# 예약 발행 — 설계

만든 카드를 **정해 둔 시각에** 인스타그램에 올린다. 지금은 "인스타에 올리기"를 눌러야만 올라간다.

---

## 지금 구조로는 안 되는 것

실제 코드를 읽고 확인한 제약이다.

| 지금 | 예약에 필요한 것 |
|---|---|
| 공유 저장소가 **프로세스 메모리**(`globalThis.__repickShareStore`, `share-store.ts`) | 서버가 재시작해도 살아남아야 한다 |
| 공유 토큰 **30분 만료**(`SHARE_TOKEN_TTL_MS`) | 몇 시간 뒤에도 인스타가 사진을 가져가야 한다 |
| 게시가 **사용자 클릭**(`POST /api/publish`)으로만 시작 | 시각이 되면 스스로 시작해야 한다 |
| `PUBLIC_BASE_URL` 을 부팅 시점 `process.env` 에서 읽음 | 터널을 다시 켜면 주소가 바뀐다 |

---

## 구조

### 예약할 때

렌더된 PNG 를 **디스크에 저장**하고 예약 항목을 기록한다.

```
.repick/scheduled/<id>/1.png … n.png     ← 이미지 (git 에 올리지 않는다)
.repick/scheduled/queue.jsonl            ← 예약 항목
```

메모리에 두면 서버 재시작에 날아간다. 카드 내용은 **예약한 순간에 고정**된다 — 나중에 카드를
고쳐도 예약된 것은 그대로 올라간다(예약할 때 본 그대로가 올라가야 한다).

한 항목: `{ id, scheduledAt, caption, imageCount, status, createdAt, result? }`
`status` ∈ `pending | published | failed | missed | canceled`

### 시각이 되면

`instrumentation.register()`(서버 기동 훅 — 토큰 자동 갱신이 이미 쓰는 자리)에서 스케줄러를
켠다. **1분마다** 도래한 항목을 확인한다.

도래한 항목 처리:

1. **디스크 이미지로 공유 토큰을 새로 발급한다** — 예약 시점 토큰은 이미 만료됐다
2. `PUBLIC_BASE_URL` 을 **`.env.local` 에서 다시 읽는다**(부팅 시점 값이 아니라). 터널을 새로
   켜서 주소가 바뀌어도 서버 재시작 없이 반영된다 — `instagram-token-refresh-runtime.ts` 가
   이미 `.env.local` 을 다루는 전례가 있다
3. **터널이 실제로 닿는지 확인한다** — 발급한 이미지 주소 하나를 직접 불러 본다. 안 닿으면
   게시하지 않고 `failed` 로 이유를 남긴다(인스타에 깨진 요청을 보내지 않는다)
4. 게시한다(`publishCarousel`, 기존 경로 그대로)
5. 결과를 기록하고 이미지를 지운다

### 놓친 예약 — 유예 1시간

서버가 꺼져 있어서 시각을 넘긴 항목:

- **예약 시각 + 1시간 이내** → 올린다(잠시 껐던 경우를 구제)
- **넘었으면** → `missed` 로 남기고 올리지 않는다

새벽에 서버를 켰다가 어제 낮 예약이 올라가는 일을 막는다. 화면이 놓친 항목을 보여 주고,
사용자가 원하면 다시 예약할 수 있다.

## 화면

내보내기 화면의 인스타 패널 안에 둔다 — 지금 "인스타에 올리기" 버튼 옆.

- **시각 선택** + `예약하기`. 과거 시각은 막는다
- **예약 목록**: 시각 · 상태 · 카드 수. `pending` 은 취소할 수 있다
- 상태별 문구는 전부 한국어. 실패는 **왜 실패했는지**(터널 안 닿음 / 토큰 만료 / 한도 초과)
- 목록은 예약이 하나라도 있을 때만 보인다

---

## 정직하게 말할 한계 — 화면에 적는다

**컴퓨터가 켜져 있고 dev 서버와 터널이 돌고 있어야 올라갑니다.** 로컬 앱의 구조적 제약이라
우회할 수 없다. 예약 화면에 이 문장을 그대로 둔다 — 안 적으면 "예약했으니 됐다"고 믿고 컴퓨터를
끈다.

`cloudflared` 빠른 터널은 켤 때마다 주소가 바뀐다. 예약해 둔 사이 터널을 다시 켰다면
`.env.local` 의 `PUBLIC_BASE_URL` 을 갱신해야 한다.

---

## 안전

- 예약·취소·목록 API 는 **이 PC 브라우저에서만**(`isLocalHost`) — 기존 게시 API 와 같다
- 인스타 **하루 100건** 한도는 기존 게시 경로가 이미 다룬다. 예약이 그 한도를 우회하지 않는다
- 예약 항목에 **토큰·시크릿을 담지 않는다**. 게시 시점에 `.env.local` 에서 읽는다
- `.repick/` 은 `.gitignore` 에 넣는다 — 카드 이미지가 저장소에 올라가면 안 된다
- 스케줄러는 **한 항목씩 순차로** 처리한다. 같은 항목이 두 번 올라가지 않게 처리 중 표시를 둔다

---

## 범위 밖

- 반복 예약(매주 화요일 등) — 한 번짜리부터
- 컴퓨터가 꺼져 있어도 올리기 — 클라우드가 필요하다
- 예약 시각 수정 — 취소하고 다시 잡는다
- 예약 후 카드 수정 반영 — 예약 시점에 고정한다(위 참조)

## 테스트

이 저장소 vitest 는 `environment: "node"` 라 **React 렌더 테스트를 쓸 수 없다.** 판단 로직은
순수 함수로 빼서 테스트한다:

- 도래 판정(유예 1시간 포함) — 시각을 인자로 받아 `Date.now()` 에 기대지 않는다
- 상태 전이(`pending → published/failed/missed/canceled`)
- 큐 파일 읽기·쓰기(임시 디렉토리)

**실제 인스타 게시는 자동 테스트로 하지 않는다** — 진짜로 올라간다. 스케줄러가 게시 함수를
부르는지까지만 mock 으로 확인하고, 실제 게시는 사람이 한 번 예약해 확인한다.
