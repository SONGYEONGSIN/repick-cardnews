# 카드뉴스 플로우를 새 IA·새 디자인으로 구현

- 날짜: 2026-08-01
- 대상: 카드뉴스 플로우 (`src/features/cardnews/**`) + 새 셸
- 성격: 시안(`/lab2`)을 실제 동작하는 화면으로 승격. 전체 재개편의 **첫 조각**

## 배경

`/lab2` 에 D2 무채색 캔버스 방향으로 전체 흐름 시안을 만들고 사람이 확인했다. 이제 그것을
실제로 동작하게 만든다. 시안은 시각적으로 확정된 상태이므로 이 스펙은 **무엇이 바뀌고
무엇이 그대로인지**만 정의한다.

## 조각 나누기

전체 재개편은 넷으로 자른다. 이 스펙은 **1번**만 다룬다.

| 조각 | 내용 | 이 스펙 |
|---|---|---|
| 1 | 카드뉴스 플로우를 새 IA·새 디자인으로 동작 | **대상** |
| 2 | 형광 강조 · 캡션 · 인스타 올리기 · 되돌리기 | 범위 밖 |
| 3 | 정보전달 플로우 | 범위 밖 |
| 4 | 카드 템플릿 재디자인 | 범위 밖 |

## 지금 상태

**단계 순서가 시안과 다르다.** 현재는 사진이 먼저다.

```
현재  1 사진 → 2 순서 정하기 → 3 주제 → 4 편집 → 5 내보내기
새것  1 주제 → 2 만들기 → 3 내보내기
```

`/api/generate` 가 키워드와 사진을 **함께** 받으므로 둘 다 성립한다. 주제를 먼저 받는 쪽으로
바꾸는 이유는 도구를 열 때 사용자가 들고 오는 것이 주제이기 때문이다 — "무엇을 만들까요"를
묻는 화면이 따로 있을 이유가 없다.

셸은 `StudioShell`(사이드바 + 헤더 + 푸터, plum 액센트)이고, **정보전달 플로우가 같은 셸을
쓴다.** 조각 3 전까지 두 셸이 공존해야 한다.

## 새 구조

### 화면 셋

| 화면 | 합쳐진 것 | 하는 일 |
|---|---|---|
| **주제** | 허브 + 기존 3단계(주제) | 키워드 입력, 종류 선택, 최근 목록 |
| **만들기** | 기존 1·2·4단계(사진·순서·편집) | 사진 올리기, 순서, 카피 생성, 카드 편집 |
| **내보내기** | 기존 5단계 | 세트 확인, 저장 |

### 단계 게이트

- 주제 → 만들기: 키워드가 비어 있지 않을 것
- 만들기 → 내보내기: 슬롯에 사진 5~6장 **그리고** 카피가 생성돼 있을 것

기존 `canLeaveOrder` 가 5~6장 조건을 이미 갖고 있으므로 그대로 쓴다.

### 카피 생성 시점

기존에는 3단계(주제)에서 눌렀다. 새 구조에서는 **만들기 화면 안**에서 실행한다 — 사진이 5장
이상 차면 "카피 생성" 이 활성화된다. 생성 전에는 캔버스에 빈 상태를 보여 준다.

### 편집 표면

시안 그대로다.

- **캔버스가 편집 표면** — 헤드라인·본문을 눌러 그 자리에서 고친다
- **툴바가 유일한 컨트롤 표면** — 윗줄에서 고칠 대상(헤드라인·본문·사진·카드)을 고르면 아랫줄이 통째로 바뀐다
- **초점은 사진 위에서 끌어서** — 가로·세로 슬라이더를 없앤다
- 순서 레일은 가로. 안 쓴 사진이 같은 축 끝에 붙는다
- 세트 단위(테마·핸들)는 상단 세트 바에

## 상태 변경

`CardnewsState` 의 필드는 **그대로 둔다**. 바뀌는 것은 단계 의미뿐이다.

| 항목 | 현재 | 새것 |
|---|---|---|
| `step` | 1~5 | **0~2** |
| `initialCardnewsState.step` | 1 | **0** |
| `themeId` 기본값 | `mint-clean` | 그대로 |

화면 안에서만 쓰는 상태(선택된 카드 인덱스, 툴바가 고른 요소)는 reducer 가 아니라
만들기 화면의 지역 상태로 둔다 — 저장할 값이 아니고 되돌리기 대상도 아니다.

`UPDATE_CARD` 의 `patch` 로 카피 수정이 이미 가능하므로 인라인 편집에 새 액션이 필요 없다.

## 디자인 규율

D2 는 **액센트 색을 쓰지 않는다** — 강조는 검정 채움(`bg-ink text-surface`)과 굵기로 만든다.
다만 `plum` 토큰을 지우지 않는다. 정보전달 플로우가 아직 쓰기 때문이다. 즉 이것은 토큰 삭제가
아니라 **새 화면에서의 사용 규율**이다.

폰트 웨이트는 400 / 700 / 900 세 종을 쓴다(기존 화면은 400/600/800 유지 — 조각 3에서 통일).

## 검증

1. **기존 테스트가 계속 통과** — `reducer.test.ts`·`render.test.ts` 등 191개. 단계 번호를 쓰는 테스트가 있으면 새 의미로 고친다
2. **새 게이트 테스트** — 주제→만들기, 만들기→내보내기 조건을 순수 함수로 뽑아 테스트
3. `npx tsc --noEmit` 0바이트, `npm test` 전부 통과, 디자인 게이트 통과
4. **폭 스위프** — 390 / 768 / 1024 / 1280 / 1440 / 1920 오버플로 0
5. **Lighthouse 접근성** — 세 화면 모두 95 이상
6. **실제 생성 1회** — 사진 없이는 불가하므로 사람이 사진을 넣고 끝까지 한 번 돌린다

## 범위 밖

- 형광 강조 지정, 캡션 생성, 인스타 올리기, 되돌리기 (조각 2)
- 정보전달 플로우와 `StudioShell` 제거 (조각 3)
- 카드 템플릿·테마 재디자인 (조각 4)
- 툴바의 **글자 크기·정렬·글 위치·사진 배율** — 시안에는 있으나 `CardDraft` 에 대응 필드가 없다(가진 것은 `layout`·`focal`·`scrim`·`band`·`copy` 뿐). 필드를 늘리면 템플릿 렌더도 같이 고쳐야 하므로 조각 2 에서 함께 한다. 조각 1 의 툴바에는 **데이터 모델이 이미 받는 것만** 올린다 — 구성(`layout`), 초점(`focal`), 글 배경(`scrim`), 사진 높이(`band`), 사진 바꾸기(`SWAP_IN`)
