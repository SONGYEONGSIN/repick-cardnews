# 늘 켜 두는 맥에 올려 도메인으로 쓰기 — 설계

**날짜** 2026-08-06 · **상태** 설계 확정, 구현 전

## 왜

지금은 개발 서버(`npm run dev`)를 띄운 동안에만 도는 **로컬 스튜디오**다. 그래서 셋이 걸린다.

- 맥이 잠들거나 개발 서버를 끄면 **예약 발행이 멈춘다**
- 인스타그램에 올리려면 공개 주소가 필요한데, 무료 터널은 **켤 때마다 주소가 바뀌어**
  `PUBLIC_BASE_URL` 을 매번 고쳐야 한다
- 밖에서·폰에서 쓸 수 없다

늘 켜 두는 맥에 올리고 고정 도메인을 붙여 셋을 한 번에 없앤다.

## 무엇을 만드는가

**늘 켜져 있는 데스크톱 맥 한 대 위의, 나 혼자 쓰는 서비스.** 여러 사용자용이 아니다.

```
폰·노트북 브라우저 ──HTTPS──▶ Cloudflare ──[Access: 내 이메일만]
                                   │
                            이름 있는 터널 (cloudflared)
                                   │
                            맥 ─ next start (3500)
                                 ├─ claude -p          (카피 생성)
                                 ├─ .env.local          (설정·인스타 토큰)
                                 └─ 예약 큐·카드 이미지

인스타그램 서버 ─────HTTPS──▶ Cloudflare ──[/s/* 는 우회]──▶ 맥
```

도메인 이름은 설정할 때 정한다. 이 문서는 `<도메인>` 으로 적는다.

## 앱 코드는 거의 그대로다

이 설계가 앱에서 바꾸는 것은 **없다**. 아래는 이미 자기 자리에 있다.

| 이미 되는 것 | 어디 |
|---|---|
| 인스타 토큰 자동 갱신이 `.env.local` 을 다시 씀 | `src/lib/instagram-token-refresh.ts` |
| 예약 스케줄러가 서버 기동 때 켜짐 | `src/instrumentation.ts` |
| 스케줄러가 `.env.local` 의 공개 주소를 매 틱 다시 읽음 | `src/lib/schedule-runner.ts:54` |
| 스케줄러가 멈추면 화면이 경고 | `src/lib/scheduler-health.ts` |
| 인스타가 가져갈 이미지 경로 | `src/app/s/[token]/[image]/route.ts` |
| 폰에서 결과물 받기(브라우저 다운로드) | `src/lib/export.ts` → `useExport.ts:30` |

바뀌는 것은 **어디서 어떻게 돌리느냐**와 **앞에 누가 서 있느냐**뿐이다. 앱 코드 변경은 0줄,
설정은 `.env.local` 에 한 줄 추가(아래 "데이터가 어디 사는가")가 전부다.

## 결정 1 — 로그인은 앱 밖에 둔다 (Cloudflare Access)

앱에는 로그인이 없다(`src/middleware.ts` 없음). 도메인을 붙이는 순간 주소를 아는 누구나
사장님 인스타 계정으로 게시할 수 있으므로 **로그인은 선택이 아니다.**

**앱 안에 만들지 않고 터널 앞에 세운다.**

이 앱은 인스타 계정 게시 권한을 들고 있다. 세션·쿠키·상수시간 비교를 직접 짜다 한 군데
틀리면 그 권한이 열린다. 사용자가 한 명인데 위험은 계정 전체다 — **안 만드는 쪽이 안전하다.**

Access 정책 두 개:

| 대상 | 정책 | 왜 |
|---|---|---|
| `<도메인>/*` | 내 이메일만 통과 | 화면·API 전부 |
| `<도메인>/s/*` | **우회(bypass)** | 인스타그램 서버가 이미지를 가져가야 한다 |

`/s/*` 는 추측할 수 없는 토큰이 지킨다(`src/lib/instagram.ts:213`).

**치르는 값**: 이 설정은 저장소 밖(Cloudflare)에 있어 `npx vitest`·`npm run design:audit`
가 못 잡는다. 그래서 **아래 검증 절차가 유일한 안전망**이고, 문서로만 남는다.

Cloudflare 화면의 메뉴 이름과 단계는 이 문서에 적지 않는다 — 바뀌는 값이고 확인하지 않았다.
**정책이 제대로 걸렸는지는 화면 설명이 아니라 아래 검증으로 판단한다.**

## 결정 2 — 운영본을 별도 폴더에 clone 한다

`next dev` 와 `next start` 는 **같은 `.next` 폴더를 쓴다.** 한 폴더에서 둘 다 돌리면
개발할 때마다 운영이 깨진다.

운영본을 따로 clone 한다(`~/repick-prod`). 그러면

- 개발은 지금 폴더(`~/개발/build/repick-cardnews`)에서 그대로 계속한다
- 배포는 `git pull → npm ci → npm run build → 재시작` 넉 줄이다
- 예약 데이터·저장된 카드가 개발본과 자연히 분리된다

`.env.local` 은 운영본에 따로 둔다. 개발본과 **`PUBLIC_BASE_URL` 만 다르다**(그리고 아래
`REPICK_SCHEDULE_ROOT` 한 줄이 붙는다).

**값 옮기기는 사람이 한다.** 저장소 규칙상 나는 `.env.local` 을 열지 않고 값을 보고서·로그에
옮기지도 않는다.

## 결정 3 — LaunchAgent 로 띄우고 자동 로그인을 켠다

`claude -p` 는 로컬 OAuth 자격으로 돈다. 그 자격은 사용자 세션에 묶여 있으므로

- **LaunchDaemon(부팅 시 root)이 아니라 LaunchAgent(사용자 세션)** 로 띄운다
- 재부팅 뒤에도 세션이 있어야 하므로 **자동 로그인을 켠다**

등록 대상 둘: **웹 서버**(`npm run start`)와 **터널**(`cloudflared`). 둘 다 죽으면 다시 뜨고
재부팅해도 올라온다.

**잠자기를 끈다** — 지금 `sleep 1` 이라 방치하면 1분 뒤 잠든다. 데스크톱이라 뚜껑 문제는 없다.

## 데이터가 어디 사는가

| 무엇 | 어디 | 손댈 것 |
|---|---|---|
| 인스타 토큰·설정 | 운영본 `.env.local` | 없음 |
| 예약 큐·카드 이미지 | 기본은 운영본 `.repick/` | **`~/repick-data/scheduled` 로 뺀다** |
| 저장한 카드 | 운영본 `cardnews/`·`informationsend/` | 없음 |

예약만 밖으로 빼는 이유: `.repick/` 는 저장소 폴더 안이라 `git clean -fdx` 한 번에 예약이
통째로 사라진다. `REPICK_SCHEDULE_ROOT` 한 줄이면 없앨 수 있는 위험이다
(`src/lib/schedule-queue.ts:41` 이 이미 이 환경변수를 본다 — 새로 만들 것이 없다).

## 오류가 났을 때

| 무엇이 죽나 | 무엇이 알아채나 | 사용자가 보는 것 |
|---|---|---|
| 웹 서버 | LaunchAgent 가 다시 띄운다 | 잠깐 안 열리다 돌아온다 |
| 터널 | LaunchAgent 가 다시 띄운다 | 잠깐 안 열리다 돌아온다 |
| 스케줄러만 | heartbeat (`scheduler-health.ts`) | 화면의 경고 문구 |
| `claude -p` | 기존 오류 변환 | 한국어 안내 |

**`claude -p` 자격이 만료되면** 카피 생성만 실패한다. 화면은 한국어로 알려 주지만
고치려면 맥에서 직접 다시 로그인해야 한다 — 밖에서는 못 고친다. 받아들이는 제약이다.

## 검증

### 먼저 확인할 것 — 여기서 갈린다

**LaunchAgent 로 띄운 프로세스에서 `claude -p` 가 도는가.** 백그라운드 프로세스는 환경과
키체인 접근이 로그인 세션과 다를 수 있다. **이게 안 되면 카피 생성이 통째로 죽고 설계를
다시 짜야 한다.** 그래서 다른 것을 만들기 전에 이것부터 본다.

### 그다음

| 확인 | 어떻게 | 통과 기준 |
|---|---|---|
| 프로덕션 빌드 | 운영본 폴더에서 `npm run build` | 성공. **이 저장소에서 한 번도 안 돌려 봤다** |
| Access 가 막는가 | 로그아웃 상태로 `<도메인>/` | 로그인 화면 |
| `/s/*` 예외 | 없는 토큰으로 `<도메인>/s/없는토큰/1.png` | **앱의 404**. Access 로그인 화면이 나오면 예외가 안 걸린 것 |
| 예약 발행 | 고정 주소로 1건 실제 예약 | 인스타에 올라감 |
| 재부팅 | 맥을 껐다 켠다 | 로그인 없이 서버·터널이 스스로 올라옴 |

### 사람이 봐야 하는 것

- **폰에서 사진 넣기** — `Dropzone.tsx:76` 이 폴더 통째 선택(`webkitdirectory`)인데 iOS
  사파리는 이 속성을 무시한다. 무시되면 일반 사진 선택으로 떨어져 **아마 동작하지만
  확인한 적이 없다**
- **폰에서 작업대 화면** — `design:audit` 폭 스위프는 `/`·`/info` 만 훑는다. 사진과 카드가
  있어야 열리는 화면은 자동으로 안 잡힌다

## 하지 않는 것

- 여러 사용자 · 앱 안 로그인 · 컨테이너 · 자동 배포(CI)
- 개발본과 운영본의 데이터 공유
- 폰 전용 화면 새로 만들기 — 지금 반응형으로 쓸 만한지 **먼저 보고** 판단한다
