# 정보전달을 카드뉴스와 같은 수준으로 — 설계

정보전달(인포그래픽 한 장)을 카드뉴스와 **같은 흐름·같은 도구**로 맞춘다.

---

## 먼저 정리 — 이미 되어 있는 것

**"HTML 로 만들고 인스타 이미지로 변환"은 이미 지금 구조다.** 새로 만들 필요가 없다.

```
src/templates/**  (React = HTML)  →  html-to-image toBlob  →  1080×1350 PNG
```

카드뉴스와 정보전달이 **같은 파이프라인**(`src/lib/export.ts`)을 쓴다. 정보전달도 이미
`InfographicBody` 라는 HTML 템플릿으로 그려져 PNG 가 된다.

그러니 이 작업은 "변환 방식을 바꾸는 일"이 아니라 **흐름과 도구를 맞추는 일**이다.

---

## 지금 벌어져 있는 것

| | 카드뉴스 | 정보전달 |
|---|---|---|
| 흐름 | 주제 → 만들기 → 내보내기 (3화면) | 사진 → 주제 → 편집 → 내보내기 (**4단계 위저드**) |
| 사진 | 5~6장 필수 | **1장 필수** (`canLeavePhoto` 가 막는다) |
| 편집 | 캔버스에서 직접 + 툴바 | 옆 패널 입력칸 |
| 테마 | 6종, 툴바 탭 | 있으나 조작 자리 없음 |
| 점검 | 사이드바 점검 목록 | 없음 |
| 내보내기 | 파일·폰·인스타 3방법 + 예약 | **파일 저장만** |
| 소재 찾기 | 있음 | 없음 |

---

## 무엇을 만드나

### A. 3화면으로

`주제 → 만들기 → 내보내기`. 카드뉴스와 **같은 `StudioFrame` 스텝**을 쓴다.

- 사진 단계를 없앤다 — 사진은 '만들기' 안에서 **선택적으로** 넣는다
- 편집은 캔버스에서 직접(카드뉴스와 같은 방식)

### B. 사진을 선택사항으로

`canLeavePhoto` 가 지금 사진을 강제한다. 렌더 쪽(`toRenderCard`)은 이미 `photoUrl: … ?? null`
로 **없어도 되게** 돼 있다 — **틀은 준비돼 있고 흐름만 막고 있다.**

- 사진 없이도 만들기·내보내기까지 갈 수 있다
- 사진을 넣으면 지금처럼 위쪽 띠에 들어간다

### C. 사진이 없을 때의 배경 — **제목 띠**

사진 자리(`band` 만큼의 위쪽 영역)를 비워 두지 않고 **테마 색으로 채운 제목 띠**로 바꾼다.

```
┌─────────────────────────┐
│  ███ accent 로 채운 띠 ███ │   ← 제목이 onPhoto 색으로 크게
│                         │
├─────────────────────────┤
│  ① 키워드 — 설명          │   ← bg 위에 항목들
│  ② 키워드 — 설명          │
│  ③ 키워드 — 설명          │
│                         │
│  팁 한 줄                 │
└─────────────────────────┘
```

**새 그림 자산을 만들지 않는다.** `theme.accent`·`theme.bg`·`theme.onPhoto` 세 값이면 된다 —
테마를 바꾸면 띠 색도 함께 바뀐다. 인포그래픽 포스터가 실제로 이렇게 생겼다.

**사진이 있으면** 지금대로 사진이 그 자리에 들어간다. 즉 **띠는 사진의 대역**이지 별개 모드가
아니다 — 레이아웃이 하나라 코드가 갈라지지 않는다.

대비: 띠 위 제목은 `onPhoto`(여섯 테마 모두 흰색), 띠 배경은 `accent`. `themes.test.ts` 가 이미
**accent 위 흰 글자 대비**를 지키고 있다(사진 위 가림막과 같은 기준).

### D. 카드뉴스가 얻은 것 이식

- **캔버스 직접 편집** — 제목·부제·항목·팁을 그 자리에서 고친다
- **툴바** — 조작 줄 / 안내 줄. 탭: `제목` `항목` `사진` `카드` `테마`
- **점검 목록** — 사이드바에. 빈 항목·글자 수 초과·사진 없음(선택이므로 경고 아님)
- **내보내기 3방법 + 예약 발행** — 카드뉴스와 같은 화면·같은 부품을 쓴다
- **소재 찾기** — 주제 화면에서 같은 패널을 연다

이식은 **같은 부품을 재사용**한다. `ExportScreen`·`SchedulePanel`·`MaterialFinderScreen` 은
카드 배열이 아니라 **이미지 배열**에만 기대므로, 정보전달(1장)도 그대로 쓸 수 있다.

---

## 하지 않는 것

- **인포그래픽을 여러 장으로** — 한 장이 이 형식의 정의다
- **새 그림 자산·아이콘 세트** — 테마 값만으로 만든다
- 카드뉴스와 정보전달의 **코드 통합** — 스펙이 다르다(`InfographicSpec` vs `CardnewsSpec`).
  화면 부품은 공유하되 상태·템플릿은 따로 둔다

---

## 안전·품질

- 새 화면도 `docs/ui-standards.md` 를 따른다 — 패널 골격, 폭, 2단, 호버, 빈 자리 박스
- **정렬 게이트에 정보전달 경로를 추가한다**(`scripts/design-audit.mjs`). 지금 게이트는
  카드뉴스만 밟는다 — 나란한 것을 새로 만들면 게이트도 함께 늘린다
- 판단 로직은 순수 함수로 빼서 테스트한다(vitest 가 `environment: "node"` 라 렌더 테스트 불가)
- 손으로 베낀 값은 테스트로 묶는다(스키마 상한 등)

---

## 순서

한 번에 다 하지 않는다. 각 조각이 **혼자서도 동작하는 상태**로 끝난다.

1. **사진을 선택사항으로 + 제목 띠** — 지금 4단계 흐름 그대로, 사진 없이도 만들어진다
2. **3화면 IA** — 주제/만들기/내보내기로 재구성, 캔버스 직접 편집과 툴바
3. **내보내기 이식** — 3방법 + 예약 발행
4. **소재 찾기 · 점검 목록 · 정렬 게이트**

1번만 끝나도 "사진 없이 정보전달을 만든다"는 목적은 달성된다.
