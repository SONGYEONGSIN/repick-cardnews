# 스튜디오 UI 에 repick-design 크래프트 규율 적용

- 날짜: 2026-08-01
- 대상: 카드 스튜디오의 앱 UI (`src/templates/**` 제외)
- 성격: 크래프트 개편 — 정보 구조와 단계 흐름은 바꾸지 않는다

## 배경

현재 스튜디오 UI 가 "AI 가 만든 티"로 읽힌다. `repick-design` 레포에 축적된 디자인 규율을
이 프로젝트에 옮겨 출시 수준으로 끌어올린다.

`repick-design` 은 npm 패키지도 배포된 토큰도 아니고 레포로만 존재한다. 따라서 "설치"가 아니라
필요한 규칙을 **골라서 옮겨오는** 작업이다. 그 레포의 디자인 시스템은 `vault/` 에 있다:

| 문서 | 역할 |
|---|---|
| `00-principles/page-brief-core.md` | 전 페이지 타입 공통 강제 규칙 |
| `00-principles/dash-brief-v3.md` | `dashboard`·`settings` 프로파일 (앱 셸·컴포넌트 시스템) |
| `20-catalog/colors.catalog.md` | AA 보정된 팔레트 뱅크 |
| `20-catalog/{motion,ux-guidelines,charts}.catalog.md` | 카탈로그 |
| `scripts/gate.mjs` + `scripts/dash-static-check.mjs` | 기계 게이트 |

repick DNA 는 "무채색 위계 + 극소량 단일 액센트 + 진짜 라이트(크림·페이퍼 금지)"다.

## 이 vault 를 그대로 적용할 수 없는 이유

vault 는 **디자인 진화 쇼케이스**를 위해 쓰였다. 심사받는 후보 페이지를 만드는 규칙이라
실제 제품에 그대로 오면 곤란한 항목이 있다.

| 규칙 | 왜 적용하지 않는가 |
|---|---|
| `page-brief-core §1` 카피 영문 전용, 한글 혼용 금지 | 이유가 "글로벌 벤치마크 정합"이다. 한국어 인스타 콘텐츠 도구에 적용할 규칙이 아니다 |
| `dash-brief-v3` 데이터 테이블·차트 크로스헤어·인터랙션 4종 | 스튜디오는 4단계 위저드다. 테이블도 차트도 없다 |
| "제품·브랜드는 자유 발명" | RE:픽이 이미 있다 |

반대로 좌측 사이드바 앱 셸 요구는 **이미 충족돼 있다** — `StudioShell` 이 사이드바(브랜드 락업 +
StepRail + 하단 메타) + 헤더 + 푸터 구조를 갖고 있다. 그래서 남는 것은 순수하게 크래프트다.

## 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 개편 대상 | 스튜디오 UI 만 | 카드 이미지는 인스타 피드에서 눈에 띄어야 해서 "무채색 + 극소량 액센트"가 오히려 독이 될 수 있다. 별도 판단이 필요하다 |
| 구조 | 위저드 유지, 크래프트만 적용 | AI 티는 구조가 아니라 마감(중성색 틴트·대비 미달·토큰 빈틈)에서 나온다 |
| 액센트 | plum `#7A2E6B` 유지 | vault 규칙은 "무채색 위계 + 단일 액센트"라는 **구조** 규칙이지 색상 지정이 아니다. 색까지 같이 바꾸면 무엇이 개선됐는지 구분할 수 없다. 흰 배경 대비 8.64:1 로 AA 도 넉넉하다 |
| 중성색 | zinc 계열 순백 기반으로 교체 | 현재 중성색이 전부 마젠타 틴트라 액센트와 뭉갠다 |
| 디스플레이 폰트 | 스튜디오는 Pretendard 단독 | vault 화이트리스트 3종은 전부 라틴 전용이라 한글 UI 에서 워드마크에나 쓸 수 있다. 폰트를 하나 더 받을 이유가 없다 |
| 기계 게이트 | 선별 이식 | 아래 "게이트" 절 참조 |
| 다크 모드 | 도입하지 않음 | 현재 없고, 이번 작업의 목표가 아니다 |

**Gaegu·Do Hyeon 은 제거하지 않는다.** 카드 템플릿(`templates/themes.ts`)이 실제로 쓰고 있고
범위 밖이다. 스튜디오 쪽 정리 대상은 `globals.css` 의 **미사용** `--font-display` 변수뿐이다.
Pretendard 는 jsDelivr CDN 으로 이미 정상 로드된다.

카피의 이모지 규칙(`knowledge/brand-voice.md` "카드당 0~2개")도 **그대로 둔다** — 그건 카드 카피
규칙이고, `no-emoji` 게이트는 스튜디오 UI 코드에만 적용된다. 현재 스튜디오 UI 에 이모지는 없다.

## 측정된 결함 (기준선)

설계의 출발점은 추측이 아니라 실측이다. 실행 중인 dev 서버(`localhost:3500/cardnews`)에
Lighthouse 접근성 감사를 돌렸다.

**접근성 92점 — 게이트 기준 95 미달.** 실패 감사 2건:

1. **`color-contrast`** — `#8b8791`(=`ink3`) on `#ffffff` 에서 **3.51:1**. 걸린 노드는
   사이드바 플로우 라벨(11px), 사이드바 하단 메타(11px), 푸터 안내(14px).
2. **`label`** — `Dropzone` 의 숨은 파일 입력(`<input type="file" class="sr-only">`)에
   연결된 `<label>` 도 `aria-label` 도 없다. 접근 가능한 이름이 없는 컨트롤이다.

토큰 단위로 계산하면 이렇다. 계산값은 Lighthouse 실측과 일치한다(3.52 계산 / 3.51 실측).

| 토큰 | 배경 | 명암비 | 판정 |
|---|---|---|---|
| `ink3 #8B8791` | `surface #FFFFFF` | **3.51:1** (실측) | AA 본문 4.5:1 **미달** |
| `ink3 #8B8791` | `canvas #FBFAFB` | **3.38:1** | **미달** |
| `text-ink-3/60` (StepRail 비활성 단계) | `surface #FFFFFF` | **약 2:1** | 심각 미달 |
| `ink2 #57545C` | `canvas #FBFAFB` | 7.26:1 | 통과 |
| `plum #7A2E6B` | `surface #FFFFFF` | 8.64:1 | 통과 |

`ink3` 는 힌트(`Field`), 사이드바 메타, 푸터 안내, 헤더 스텝 번호, 사진 장수 표시에 쓰인다 —
전부 본문급 보조 텍스트다.

**목표: 접근성 95 이상.** 위 2건이 이번 개편의 정량 성공 기준이다.

## 새 토큰 램프

zinc 계열로 교체하고, `page-brief-core §3` 의 **표면 톤 조건부 하한**을 그대로 적용한다.

| 토큰 | 값 | 흰 배경 대비 | `hairSoft` 위 대비 |
|---|---|---|---|
| `canvas` | zinc-50 `#FAFAFA` | — | — |
| `surface` | `#FFFFFF` | — | — |
| `hairSoft` | zinc-100 `#F4F4F5` | — | — |
| `hair` | zinc-200 `#E4E4E7` | — | — |
| `ink` | zinc-900 `#18181B` | 17.72:1 | 16.1:1 |
| `ink2` | zinc-600 `#52525B` | 7.73:1 | 7.03:1 |
| `ink3` | zinc-500 `#71717A` | 4.83:1 | **4.39:1 — 미달** |

**`ink3` 사용 규칙**: 순백·`canvas` 표면에서만 쓴다. `hairSoft` 이상의 muted 표면(세그먼트 트랙,
탭, 배지, 필) 위 보조 텍스트는 `ink2` 를 쓴다. 이 4.39:1 수치는 vault 가 실측으로 기록한 값
(`neutral-500` on `neutral-100` = 4.34:1)과 독립 계산으로 일치한다.

**투명도로 색을 흐리지 않는다.** `text-ink-3/60` 같은 표현은 계산된 대비를 무너뜨리므로 금지하고,
비활성 상태는 별도 토큰으로 표현한다.

액센트는 지금 `plum`/`plumSoft` 두 단계뿐이라 상태 표현이 부족하다. 다음을 추가한다.

| 토큰 | 값 | 용도 | 대비 |
|---|---|---|---|
| `plum` | `#7A2E6B` | 기본 액센트 | 흰 배경 8.64:1 / 흰 글자 8.64:1 |
| `plumHover` | `#66255A` | hover | 흰 글자 10.62:1 |
| `plumActive` | `#521D48` | active | 흰 글자 12.90:1 |
| `plumSoft` | `#F6EAF3` | 배지·연한 배경 | 위에 `plum` 글자 7.40:1 |
| `ring` | `#7A2E6B` | 포커스 링 | — |

`Badge` 의 warn 톤은 현재 주석 달린 arbitrary value(`bg-[#FDF1E7] text-[#8A4B12]`, 6.11:1)다.
같은 값을 토큰으로 승격한다 — 일회성이 아니라 상태 색이다.

## 컴포넌트 시스템

`Panel`·`Button`·`Badge`·`Field`·`SegmentedControl` 에 일관된 체계를 부여한다.

- **컨트롤 높이 44px 통일** (`dash-brief-v3` 앱 셸 규칙). 현재 `Button` 은 `md` 44px(h-11) / `sm` 36px 이라 `md` 는 이미 맞다. 입력·세그먼트도 같은 높이로 맞춘다.
- **radius·border·shadow 일관** — `Panel` 은 `rounded-xl`, 컨트롤은 `rounded-lg` 로 두 단계만 쓴다.
- **포커스 링 토큰화** — 지금 각 컴포넌트가 `focus-visible:outline-plum` 을 문자열로 반복한다. 공유 상수로 뺀다.
- **폰트 웨이트 3종 유지** — 현재 400(기본)·600(semibold ×28)·800(extrabold ×4)로 이미 3종이다. 늘리지 않는다.
- **접근 가능한 이름** — `Dropzone` 의 숨은 파일 입력에 `aria-label` 을 준다. 시각적으로 감춘 컨트롤도 이름이 있어야 한다.

## 게이트

`repick-design/scripts/` 의 게이트를 **선별해서** 옮긴다. 통째로는 옮길 수 없다.

**옮기는 것**

| 규칙 | 비고 |
|---|---|
| `no-emoji` | 스튜디오 UI 코드 대상. 카드 카피는 대상 아님 |
| `no-font-serif` | |
| `no-unlisted-font` | 스튜디오는 `--font-sans` 만. 카드 템플릿 경로는 제외 |
| 폭 스위프 | 1280 / 1366 / 1440 / 1600 / 1920 / 390px, 가로 오버플로 0 이면 통과 |
| Lighthouse a11y ≥ 95 | |

**옮기지 않는 것과 이유**

- **`no-raw-img`** — 스튜디오의 `<img>` 3곳(`PhotoGrid`, `SortableSlot`, `OrderStep`)은 사용자가 방금 올린 로컬 사진의 **blob URL** 이라 `next/image` 가 최적화할 수 없다. 카드 템플릿의 `<img>` 2곳은 **html-to-image 캡처 대상**이라 `next/image` 로 감싸면 래퍼와 srcset 이 캡처를 깨뜨린다. 대신 `page-brief-core §4` 의 실질 의도를 적용한다 — **이미지 컨테이너에 고정 aspect-ratio 와 배경색을 예약**해 로드 실패·지연 시 레이아웃이 무너지지 않게 한다.
- **`no-random`** — `save/route.ts` 의 원장 타임스탬프와 `useGenerate.mmdd()` 의 `new Date()` 는 렌더 결정론과 무관하다(각각 서버 기록·폴더 이름). 이 프로젝트에는 이미 "카드 템플릿 렌더에 한해 금지"라는 더 정확한 규칙이 있고 `useGenerate` 에 그 예외가 문서화돼 있다.
- **`no-dark-dim-text`** — 다크 모드를 도입하지 않으므로 검사 대상이 없다.
- **영문 전용** — 한국어 도구다.

게이트는 npm script 로 **필요할 때 돌리는** 형태로 둔다 — 커밋 훅으로 강제하지 않는다.
정적 규칙(`no-emoji` 등)은 브라우저 없이 즉시 돌고, 폭 스위프와 Lighthouse 는 dev 서버가 떠 있어야 한다.

**실행 가능성은 확인했다.** 이 프로젝트에는 "브라우저가 로컬 dev 서버에 못 닿는다"는 기록이 있었지만
그건 Chrome 확장 도구 얘기였고, 헤드리스 크롬은 문제없이 붙는다 — 위 기준선 92점이 그 증거다.
`npx lighthouse` 와 `npx playwright` 모두 사용 가능하다.

## 검증

1. **대비 단위 테스트** — 명암비를 계산하는 순수 함수를 만들고, 토큰 조합별 하한을 테스트로 고정한다. 브라우저도 네트워크도 쓰지 않고 결정론적으로 돌며, 나중에 누가 색을 만지면 즉시 깨진다. 최소 케이스: `ink`/`ink2`/`ink3` × `surface`/`canvas`/`hairSoft`, `plum` on `surface`, white on `plum`/`plumHover`, `plum` on `plumSoft`, warn 조합.
2. **폭 스위프** — 6개 폭에서 오버플로 0.
3. **Lighthouse 접근성** — 기준선 92 에서 **95 이상**으로. `color-contrast` 와 `label` 두 감사가 통과해야 한다.
4. **사람 확인** — 이 프로젝트는 브라우저가 로컬 dev 서버에 닿지 않아 최종 화면 확인은 사람이 한다.
